## Why this exists

Mainstream nutrition apps (MyFitnessPal, Cronometer, Noom) are built around Western food databases. Pakistani users get missing entries, wrong calorie estimates, or outright recognition failures for everyday dishes like **karahi**, **halwa puri**, **nihari**, or **paya**.

This is a documented research gap:
- **Scientific Reports (2025)** — no quality dataset for South Asian cuisine exists in the mainstream food-recognition literature
- **Tahir et al. (2020)** — the first Pakistani food dataset has only ~49 images per class, too few for reliable CNN fine-tuning
- **JMIR (2024)** — 70 % of users abandon health apps within 100 days, driven primarily by manual food entry

NutriSense AI fills the gap with a fine-tuned EfficientNetB0 trained on a curated multi-source South Asian dataset and shipped end-to-end through a Flask inference API and a React + Vite web dashboard.

## What it does

1. **Upload** — drag-and-drop or select a photo of any South Asian dish on the web dashboard
2. **Identify** — the CNN classifies among **270** food classes (Pakistani, South Asian, and Western)
3. **Understand** — get calories / protein / carbs / fat per standard serving plus a 2–3 sentence, goal-personalised insight generated by an LLM

No manual entry. No calorie counting. No meal plans. Just upload → understand.

## Tech stack

| Layer | Choice | Why |
|---|---|---|
| Model | **EfficientNetB0** (5.3 M params) | Best accuracy/size ratio; fits Render's 512 MB free tier as ONNX |
| Training | **PyTorch** on Modal A10G GPU | Reproducible script-based pipeline; no session caps |
| Inference | **ONNX Runtime** (CPU) | 20–40 % faster than PyTorch single-image; tiny memory footprint |
| Backend | Flask + gunicorn | Minimal overhead; four endpoints (`/health`, `/classes`, `/predict`, `/lookup`) |
| Database / Auth / Storage | **Supabase** | All-in-one free tier with PostgreSQL + RLS + Storage |
| LLM insights | **OpenRouter** (`qwen/qwen-2.5-72b-instruct`) | OpenAI-compatible API; free tier |
| Web | React 19 + Vite 5 + Tailwind 4 | Fast dev loop; standard tooling; deploys cleanly on Vercel |
| Hosting | Render (backend) · Vercel (web) | All free tiers |

|---|---|
| Classes recognised | **270** (Pakistani, South Asian, Western) |
| Top-1 accuracy (held-out validation) | **82.65 %** |

| Confidence threshold for auto-accept | 0.70 (else top-3 picker shown) |

## Academic contribution

The primary contribution is the **fine-tuned EfficientNetB0 trained on a curated multi-source South Asian food dataset**. The dataset combines:

| Source | Classes | Role |
|---|---|---|
| Food-101 | 101 | Western baseline |
| Khana 2025 (Indian food images) | 236 | South Asian backbone |
| DeshiFoodBD | 19 | Bangladeshi overlap |
| Self-scraped Pakistani | 13 | Gap-fill for dishes absent from existing datasets |
| **Unified, after curation** | **270** | all classes ≥ 100 images |

An ablation study compares EfficientNetB0 against MobileNetV2 and ResNet50 on the same train/val split with identical hyperparameters to justify the architecture choice. Grad-CAM heatmaps visualise the model's attention regions for South Asian dishes.

## API contract

### POST /predict

```
Request: multipart/form-data
  image      File    JPEG or PNG
  user_goal  string  'weight_loss' | 'muscle_gain' | 'curious'

Response 200:
{
  "top_prediction": { "label": "chicken_karahi", "confidence": 0.91 },
  "top_3": [
    { "label": "chicken_karahi", "confidence": 0.91 },
    { "label": "chicken_handi",  "confidence": 0.06 },
    { "label": "butter_chicken", "confidence": 0.03 }
  ],
  "low_confidence": false,
  "nutrition": { "calories": 320, "protein": 28, "carbs": 8, "fat": 19 },
  "insight": "Karahi is a high-protein dish — well suited to your muscle-gain goal...",
  "gradcam_sample_url": "https://...supabase.co/storage/.../chicken_karahi_gradcam.png",
  "processing_time_ms": 1240
}
```

`low_confidence: true` when `top_prediction.confidence < 0.70`. The frontend then shows a top-3 disambiguation picker.

### GET /lookup?label=<label>&user_goal=<goal>

Returns fresh nutrition + insight for a known label without re-running inference — used when the user picks a top-3 alternative.

### GET /health
```json
{ "status": "ok", "model_loaded": true, "classes": 270 }
```

### GET /classes
```json
{ "0": "achar", "1": "aloo_gobi", ... }
```

## Running locally

See [docs/setup.md](docs/setup.md) for the full checklist. Quick version:

### Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env              # fill in OPENROUTER_API_KEY + SUPABASE_*
python app.py                     # http://localhost:5000
python test_api.py                # run the integration tests
```

Set `MOCK_MODE=true` in `.env` to run without a trained `model.onnx` — useful for frontend development before training completes.

### Web

```bash
cd web
npm install
cp .env.example .env              # fill in VITE_SUPABASE_*, VITE_API_BASE_URL, VITE_OPENROUTER_KEY
npm run dev                       # http://localhost:5173
```

### Supabase

1. Create a free project at [supabase.com](https://supabase.com)
2. Paste [`supabase/schema.sql`](supabase/schema.sql) into the SQL Editor and run
3. Create two storage buckets: `scan-images` (public) and `gradcam` (public)
4. Copy the project URL, anon key, and service-role key into the `.env` files

## Deployment

- **Backend → Render** — the repo includes [`render.yaml`](render.yaml) for one-click deploys. Set `OPENROUTER_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` in the dashboard.
- **Web → Vercel** — root directory `web`, framework preset Vite (locked in `web/vercel.json`). Deploys on every push to `main`.

Full deployment steps are in [docs/hosting.md](docs/hosting.md).
